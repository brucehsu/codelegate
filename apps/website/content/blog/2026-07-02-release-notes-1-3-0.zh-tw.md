# v1.3.0

這個版本的改動主要圍繞在分支與 Git 面板：worktree session 現在可以直接 checkout 既有的分支，差異檢視在原本的左右對照之外新增了 unified 模式，同時修正了在含有大量未追蹤檔案的 repo 開啟 Git 面板時可能導致 app 當掉的記憶體暴增問題。

其餘的改動則集中在讓日常操作更順手：

- session 分頁的分支名稱會隨外部的分支切換自動更新。
- 在任何終端機面板中 Cmd+點擊連結，即可用系統預設應用程式開啟。

[按此下載 Codelegate v1.3.0](https://github.com/brucehsu/codelegate/releases/tag/v1.3.0)

## Worktree Session 可 Checkout 既有分支

新增 session 的對話方塊現在提供分支選單：worktree session 不再只能從自動建立的分支開始，你可以直接選擇任何本地分支，session 的 worktree 會 checkout 該分支，原本 repo 的 checkout 則完全不受影響。已經在其他位置 checkout 的分支會以停用狀態顯示並標明所在位置，避免同一個分支同時出現在兩個地方。

session 的清理邏輯也遵循相同原則：移除 worktree session 時只會刪除自動建立的分支，你自己選擇的分支則予以保留。這個行為會記錄在 worktree 設定中，重啟後依然一致。

## Unified 差異檢視

Git 面板的差異區域除了原本的 split（左右對照）檢視外，新增了 unified（單欄）模式，可透過差異統計旁的 Split/Unified 切換鈕切換。unified 模式會將新舊兩側合併為單欄，並在行號欄同時顯示新舊行號。它沿用與 split 檢視相同的語法標示與虛擬化捲動，因此大型差異在兩種模式下都能保持流暢。

## 修正大量未追蹤檔案造成的記憶體暴增

過去在含有大型未追蹤資料夾（例如套件快取、內嵌資料庫）或超大檔案的 repo 開啟 Git 面板時，每次掃描都會將所有未追蹤的內容完整讀進記憶體，而每個檔案的差異請求又會重複整份掃描；在差異卡片自動展開的情況下，可能同時堆疊約二十個全 repo 掃描並使 app 當掉。

這個版本重新設計了整個流程：

- 未追蹤的資料夾會如同 `git status` 一樣收合為單一項目，並以單次操作 stage。
- 未追蹤檔案的讀取上限為 2 MiB 並由共用的閘門控管，二進位檔案由開頭 8 KiB 判斷，超過 2 MiB 的已追蹤檔案一律視為二進位。
- 單一檔案的差異請求只針對該檔案本身，不再重新掃描整個區段。
- 差異內容上限為 4000 列，遭截斷時會顯示提示。
- 差異卡片改為捲動到可視範圍時才實際載入，同時進行的摘要載入也會合併為單次後續執行。

以實際數據為例，一個含有兩萬個未追蹤檔案外加一個 286 MB 記錄檔的 repo，摘要掃描現在只需 185 ms，記憶體用量尖峰約 29.5 MB。

## 其他改善

- **分支變更監控** ：每個 session 的分支名稱會定期更新，視窗重新取得焦點時也會立即更新，因此由 agent 或其他終端機所做的分支切換會直接反映在分頁上。
- **Cmd+點擊開啟終端機連結** ：在任何面板中按住 Cmd（其他平台為 Ctrl）點擊網址，即可用系統預設應用程式開啟；單純點擊不再觸發任何開啟行為。
